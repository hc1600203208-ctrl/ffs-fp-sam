# 卫星渲染与地面处理接口（v1）

## 1. 通信流程与部署边界

```text
地面 App --配置/启动/停止--> 控制链路 --参数--> 卫星渲染程序
卫星渲染程序 --双目字节包--> 数据链路 --> 地面字节转换程序
地面字节转换程序 --左/右图像--> SAM 首帧分割 + FoundationPose 跟踪
FoundationPose --位姿--> 地面 App
```

1. 地面选择目标、初始位姿、周期运动、相机标定、分辨率、目标帧率和链路速率。OBJ、MTL、PNG 纹理和标定文件应预先放在卫星可访问的位置；**参数里的路径不是模型文件内容**。
2. 地面发送配置，卫星校验文件和参数并确认；地面再发送启动命令。修改配置时先停止，再配置并启动。卫星按相同时间生成左、右两幅图像。
3. 卫星把一对图像编码为连续的 RGB565 字节流，按 32768 字节切片并限速发送。地面按帧号和片序号重组完整双目帧，缺片则丢弃该帧。
4. 地面将字节流解码成 `bgr8` 左右图像。SAM 在订阅到首张左图像后生成各目标 mask；FoundationPose 订阅双目图像并读取这些 mask，向 App 发布位姿。SAM 模型初始化发生在订阅图像之前，不能把这一段等待归因于传输。

**实现状态：**步骤 2、3 的 `SCT1` 与 `STR1` 应用层字节包均已实现。卫星需预先启动 `satellite_render_node`，它常驻等待地面配置；地面 App 每次先发幂等 STOP，收到应答后发配置，再收到成功应答后发启动，且仅在地面启动 `stereo_bytes_to_images_node`。当前星地承载方式是 ROS 2 的三个 `std_msgs/UInt8MultiArray.data` 字节话题：`/satellite/control_bytes`（地面→卫星）、`/satellite/control_ack_bytes`（卫星→地面）和 `/satellite/stereo_bytes`（卫星→地面）。换成 TCP、串口或其他链路时可保留应用层包格式，但仍需为该链路编写收发适配器。地面 SAM、FoundationPose 和 App 之间继续使用现有 ROS 2 话题。

## 2. 字节约定

- 本文偏移均从 **0** 开始，范围端点均包含在内。`u8/u16/u32` 分别为无符号 1/2/4 字节整数；所有多字节整数使用**小端序**。控制包的 `f64` 是 IEEE 754 binary64 小端浮点数。
- 一个“应用包”指一条完整的下述字节数组。ROS 2 下，一个 `UInt8MultiArray.data` 恰好对应一个应用包；ROS/DDS 自身的序列化头不属于本文协议。TCP 是字节流，必须额外加长度前缀或其他成帧机制；不能假设一次 `read` 就是一包。
- 例如使用 TCP 时，可约定每个方向均发送 `packet_length:u32`（小端，不含自身这 4 字节）后紧跟 `packet_length` 字节的完整 `STR1` 或 `SCT1` 应用包；接收端先读满 4 字节，再读满指定长度。这个外层长度前缀**不是当前 C++ 节点输出的内容**，需要由 TCP 适配器添加/剥离。若使用串口或无线电，外层成帧方式可以不同，但交给应用层的包字节必须保持一致。
- 当前图像包没有 CRC、重传、加密或跨重启会话编号。若物理链路不保证完整性、有序交付与包边界，链路层需提供这些能力，或者先扩展协议。单个完整图像应用包最大为 **32800 字节**；低 MTU 的链路不能直接把它当作一个物理帧发送。

## 3. 卫星到地面：已实现的图像包 `STR1`

每个包 = **32 字节包头 + 本包图像数据**。包头字段如下；四字节整数的第一个字节是最低有效字节。

| 字节偏移 | 长度 | 含义 |
| --- | ---: | --- |
| 0 | 1 | ASCII `S`，`0x53` |
| 1 | 1 | ASCII `T`，`0x54` |
| 2 | 1 | ASCII `R`，`0x52` |
| 3 | 1 | ASCII `1`，`0x31`；当前格式标识 |
| 4–7 | 4 | `frame_id`，`u32`；从 0 开始，每完成一对双目帧加 1，溢出后回绕 |
| 8–11 | 4 | `part_index`，`u32`；本帧分片序号，从 0 开始 |
| 12–15 | 4 | `part_count`，`u32`；本帧总分片数，等于 `ceil(4 × W × H / 32768)` |
| 16–19 | 4 | `W`，`u32`；单眼图像宽度，像素 |
| 20–23 | 4 | `H`，`u32`；单眼图像高度，像素 |
| 24–27 | 4 | `stamp_sec`，`u32`；两幅图像共同的 ROS 时间秒数 |
| 28–31 | 4 | `stamp_nsec`，`u32`；纳秒部分，应小于 1,000,000,000 |
| 32 起 | 可变 | 当前分片的原始 RGB565 数据；前面的包头不计入 `part_index` 对应的数据偏移 |

`stamp_sec/nsec` 取自**渲染结束、开始发送前**的节点时钟；它不是曝光时刻，也不是严格同步的卫星硬件时钟。非 ROS 链路可原样传递这两个字段，但若需跨机绝对时间，必须另行同步时钟。

### 3.1 图像数据每个字节的意义

把本帧各分片中偏移 32 起的数据依照 `part_index` 拼接，得到恰好 `4 × W × H` 字节的双目帧 `F`。图像按**左眼整幅、右眼整幅**排列；每幅图按从上到下、每行从左到右排列，无行填充。每像素占两个字节：

```text
pixel_index = eye × W × H + y × W + x    # eye=0 左，eye=1 右
byte_index  = 2 × pixel_index
rgb565      = F[byte_index] | (F[byte_index + 1] << 8)
R5 = (rgb565 >> 11) & 0x1f
G6 = (rgb565 >> 5)  & 0x3f
B5 =  rgb565        & 0x1f
```

也就是说，第一个字节的位 `0–4` 是蓝色低 5 位，位 `5–7` 是绿色低 3 位；第二个字节的位 `0–2` 是绿色高 3 位，位 `3–7` 是红色 5 位。`0x0000` 为黑色。地面当前按 `R8=R5×255/31`、`G8=G6×255/63`、`B8=B5×255/31` 转成 `bgr8`。这是**原始 RGB565 像素**，不是 JPEG/PNG，也没有传深度图或 mask。

分片 `i` 承载 `F[i×32768 : min((i+1)×32768, 4×W×H)]`。因此除最后一片外，包总长度为 `32+32768=32800` 字节。以 `640×480` 为例：单眼 `614400` 字节，双眼 `1228800` 字节，分 **38** 包；前 37 包各含 32768 字节数据，最后一包含 16384 字节数据；整帧应用层总量为 **1230016** 字节（含 1216 字节包头）。`10 MB/s` 指每秒 10,000,000 字节，整帧链路占用至少约 0.123 秒，不等于 `10 Mbit/s`。

### 3.2 接收和错误处理

当前地面转换节点只接受 `STR1`，校验 `W/H` 在 `1..4096`、片数、序号和当前分片长度。收到 `part_index=0` 时开始新帧；后续必须按 `0,1,...,part_count-1` 顺序到达，才发布左右图像。缺片、乱序或新帧覆盖未完成帧时，不发布该帧；当前实现不请求重发。左右图像使用相同的时间戳，发布到 `/left/image_raw`、`/right/image_raw`，并从地面本地标定文件发布 `/left/camera_info`、`/right/camera_info`。

## 4. 地面到卫星：已实现的控制包 `SCT1`

地面 App 将 `SCT1` 字节包作为 `/satellite/control_bytes` 的 `UInt8MultiArray.data` 发布；卫星解析后将应答字节包发布到 `/satellite/control_ack_bytes`。控制包和图像包使用不同的逻辑通道。

每条控制包 = 16 字节包头 + `payload_length` 字节负载：

| 字节偏移 | 长度 | 含义 |
| --- | ---: | --- |
| 0–3 | 4 | ASCII `SCT1`，依次为 `0x53 0x43 0x54 0x31` |
| 4 | 1 | `type`：`0x01` 配置、`0x02` 启动、`0x03` 停止、`0x80` 应答 |
| 5 | 1 | `flags`，本版固定 0 |
| 6–7 | 2 | 保留，固定 0 |
| 8–11 | 4 | `request_id`，`u32`；由地面递增，应答原样回填 |
| 12–15 | 4 | `payload_length`，`u32`；不含包头 |
| 16 起 | 可变 | 负载，具体格式见下文 |

`启动`和`停止`负载为空。`配置`负载顺序如下，**相对负载首字节**计算偏移：

| 相对偏移 | 长度 | 含义 |
| --- | ---: | --- |
| 0–3 | 4 | `W`，`u32`，例如 640 |
| 4–7 | 4 | `H`，`u32`，例如 480 |
| 8–15 | 8 | `target_fps`，`f64`，例如 8.0 |
| 16–19 | 4 | `bytes_per_second`，`u32`，例如 10000000；限速包含图像包头 |
| 20–21 | 2 | `object_count`，`u16`，目标数量 |
| 22–23 | 2 | 保留，固定 0 |
| 24–71 | 48 | `amplitudes[6]`，依次为 x/y/z 米、roll/pitch/yaw 度，每项 `f64` |
| 72–119 | 48 | `frequencies[6]`，顺序同上，单位 Hz，每项 `f64` |
| 120–121 | 2 | `calibration_path_length`，`u16`，后续 UTF-8 路径的字节数 |
| 122 起 | 可变 | `calibration_path_length` 字节卫星本地标定文件路径；后面紧接 `object_count` 个目标记录 |

每个目标记录依次包含：`name_length:u16`、`name_length` 字节 UTF-8 名称、`mesh_path_length:u16`、`mesh_path_length` 字节卫星本地 OBJ 路径、`initial_pose[6]:f64[6]`。初始位姿顺序为 `x,y,z`（米）与 `roll,pitch,yaw`（度），坐标系是左相机光心，旋转使用 `Rz(yaw) × Ry(pitch) × Rx(roll)`。目标 `j` 的运动按 `pose_j[k](t) = initial_pose_j[k] + amplitudes[k] × sin(2π × frequencies[k] × t)` 计算；六个振幅和频率目前对所有目标共用，`t` 从本次启动开始计秒。当前卫星渲染器按记录顺序使用网格和位姿，名称字段保留供地面识别，卫星不据此查找文件。

接收端限制单个 `SCT1` 包最多约 1 MiB、目标数 `1..32`、单个字符串 `1..4096` 字节、分辨率各轴 `1..4096`、`target_fps` 为 `(0,1000]`；速度与位姿数值必须是有限浮点数。App 当前要求至少两个目标，卫星协议本身允许一个目标。

`应答`负载固定前 3 字节为 `status:u8`、`message_length:u16`，后面是指定长度的 UTF-8 文本。当前状态码：`0` 成功、`1` 参数不合法或包格式错误、`2` 加载标定/模型失败、`3` 状态不允许。卫星按请求的 `request_id` 回应；App 必须收到配置成功应答后才发送启动。卫星只在停止状态接受重新配置。卫星程序初始化时若显式提供旧的 `mesh_paths` 等 ROS 参数，仍按旧方式直接启动；供 App 远程配置时应**不带模型参数启动**，让节点保持空闲。

目前 App 单次请求等待 60 秒，超时会报错，**不会自动重试**；协议没有去重缓存。`START` 在已运行时和 `STOP` 在已停止时会成功应答且不重复改变状态。使用不保证送达的物理链路时，应在链路适配层或后续协议版本增加应答重试与重复请求处理。

## 5. 目前两端各需要什么

| 位置 | 程序与输入 | 输出 |
| --- | --- | --- |
| 卫星 | 常驻 `satellite_render_node`；本地 OBJ/纹理/标定；订阅 `SCT1` 配置/启动/停止 | `SCT1` 应答与 `STR1` 图像包 |
| 地面链路入口 | App 发布 `/satellite/control_bytes` 并订阅 `/satellite/control_ack_bytes`；转换节点订阅 `/satellite/stereo_bytes` | 完整应用包及左右图像 |
| 地面转换 | `stereo_bytes_to_images_node`；本地同版本标定文件 | 左右 `bgr8` 图像和相机信息 |
| 地面处理与显示 | 原 FoundationPose launch、SAM、App | mask、跟踪位姿和界面预览 |

当前代码没有通过星地链路发送标定矩阵、模型文件或跟踪位姿。卫星和地面的标定文件必须对应同一套相机；仅传字符串路径并不能让另一台机器拥有文件。App 的对象路径和“Satellite calibration”输入框指向卫星上的文件；地面转换节点使用 tracker YAML 中的地面本地标定路径。若后续选择 TCP/串口/无线电，应先明确链路单包大小、乱序与误码处理，并实现 `SCT1`/`STR1` 的外层成帧适配。
