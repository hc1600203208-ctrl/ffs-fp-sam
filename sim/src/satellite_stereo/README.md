# Satellite stereo link

The cross-host deployment flow and transport-independent byte formats are specified in [INTERFACE.md](INTERFACE.md). Both `STR1` images and `SCT1` control/acknowledgement packets are implemented over separate ROS 2 byte topics.

`satellite_render_node` is a CPU only ROS 2 node. It reads OBJ triangles and PNG diffuse textures using Eigen and libpng, renders two camera views, encodes RGB565 pixels and publishes ordered 32 KiB byte packets on `/satellite/stereo_bytes` (`std_msgs/UInt8MultiArray`). `bytes_per_second` limits packet transmission to the requested rate. `stereo_bytes_to_images_node` reconstructs complete frames on the ground and publishes `/left/image_raw`, `/right/image_raw` and both camera info topics. Incomplete frames are dropped. The existing FoundationPose launch file needs no changes.

Build on both hosts: `cd sim && source /opt/ros/jazzy/setup.bash && colcon build --packages-select satellite_stereo`. On the satellite, source `sim/install/setup.bash` and start the idle node with `ros2 run satellite_stereo satellite_render_node` (no mesh arguments). On the ground, source `sim/install/setup.bash` and the tracker workspaces, then run `python3 app/satellite_stereo_multi_app.py`. The app loads the tracker YAML, lets you change object poses, satellite model paths, satellite calibration path, shared sine motion and link rate. Pressing Start sends `SCT1` STOP, CONFIG and START in order, waiting for each acknowledgement; the app starts the image converter locally. Start the existing `foundationpose_stereo_tracker_multi.launch.py` separately. The app shows the left image and primary tracked pose. Satellite and ground hosts must share the ROS domain, and satellite model/calibration paths must exist on the satellite host; the converter reads ground-local calibration from tracker YAML.

The protocol is raw RGB565 and has no network compression. At 640 × 480, one stereo pair is about 1.23 MB before packet headers. The app defaults to 8 FPS and 10 MB/s; both values can be changed in its controls before starting or restarting the renderer. The renderer logs raster and transmission time on frame 1 and every 30 frames. The receiver logs every 30 complete frames and warns if a frame is incomplete. On the supplied two meshes, a local test reconstructed 60 frames in about 8 seconds at 10 MB/s. Both nodes must be rebuilt and deployed together when the packet format changes.

The SAM first-mask node initializes one DINO/SAM pipeline per object before subscribing to `/left/image_raw`, then processes the objects sequentially after receiving the first image. Its logs now show model initialization time, first-image arrival, and each object's mask processing time. The tracker may log missing mask PNGs while waiting; that warning alone does not indicate a stereo transport failure. OBJ polygons are triangulated, but near-plane clipping, distortion and full material features are not implemented. Compare the rendered appearance with your SAM detection models before relying on first-frame segmentation.
